# 설계에 반영한 연구

2026년 11월 7일 기준이다. 원문 전체를 확인한 핵심 논문은 위키와 지식 관리 5편, 문서 검색 2편, 의사결정 모델 3편이다. Alavi와 Leidner의 지식관리 리뷰는 개념 틀을 설명하는 절을 별도로 확인했다. 각 문서에 사용한 버전, 확인한 절과 표, 원본 구현 링크를 적었다.

기업 위키 7개 사업장을 조사한 연구에서는 신규 팀원의 반복 질문을 줄이는 일이 지속적인 사용 이유 중 하나였다. 유지 담당자가 바뀌며 내용의 일관성이 떨어진 사례도 있었다. 이 앱의 다음 사용자 시험은 신규 팀원이 현재 지침을 찾는 시간과 담당자 교체 후 결정 이유를 복원할 수 있는지를 측정한다. [기업 지식관리 연구](enterprise-kms.md)

| 질문 | 조사에서 확인한 점 | 앱에 반영한 선택 |
|---|---|---|
| 문서를 어떻게 읽을 안내문으로 바꾸는가? | STORM은 자료 수집, 개요, 절 작성, 인용을 분리한다. WeAgentAI의 LLM-Wiki는 페이지와 출처를 지속적으로 갱신한다. 실제 원문 보관 함수 시험에서는 같은 제목의 수정본이 첫 원문을 대체하지 못했다. | WeKnora가 초안을 작성하고, 앱은 파일 내용과 인용 위치를 버전별로 보관한다. [위키와 지식 관리 연구](wiki-methods.md) |
| 긴 문서에서 담당자가 원문을 얼마나 빨리 찾을 수 있는가? | PageIndex의 제목 순번은 앞에 절을 넣으면 바뀌고, 내용만 고치면 그대로였다. PDF 시험에서는 쪽 범위가 유용했지만 다단 편집의 소제목을 놓쳤다. | 실제 Markdown 목차를 원문 탐색에 쓴다. 원문 경로, SHA-256과 줄 범위로 결정을 복원한다. [PageIndex 코드와 논문](pageindex.md) |
| 기한이 다르면 누가 판단하는가? | Jev의 순서를 바꾼 시험에서 8쌍 중 7쌍이 두 순서 모두 기대 라벨과 일치했다. 문맥이 부족한 한 쌍은 두 번 모두 검토 필요로 분류했다. | 공개 원문에 대해 담당자가 요청하면 Jev가 의견을 제시한다. 담당자의 결정은 별도 기록한다. [Jev, Microsoft, Kakao 비교](decision-models.md) |
| 지식그래프나 온톨로지는 어디에 쓰이는가? | Wikidata는 같은 대상에 서로 다른 주장·출처·적용 범위·선호 순위를 기록한다. Wikibase는 변경 속성의 영향을 추적한다. RDF 증분 유지 연구는 근거 삭제 뒤 결과를 유지할 조건을 다룬다. | 자료 버전, 인용문, 결정, 담당자 관계를 SQLite에 명시한다. 현재 앱은 RDF 추론이나 OWL 온톨로지 생성을 수행하지 않는다. [코드와 원문](wiki-methods.md) |

## 다음 실험

주제 이름이 같은 문장, 제목만 다른 동일 업무 지침, 적용 대상이 다른 지침, 근거가 사라진 지침을 구분한다. 독립 검토자가 기대 조치와 당시 근거 위치를 표시한 뒤 제목 규칙, 키워드 검색, WeKnora 초안, 모델 의견을 같은 자료와 권한으로 비교한다. 변경을 놓친 비율, 불필요하게 다시 연 결정, 옛 원문을 정확히 복원한 비율, 담당자 확인 시간을 측정한다. 파일 전체의 변경을 감지하는 현재 구현은 같은 파일의 무관한 문단이 바뀌어도 해당 파일을 인용한 결정을 다시 연다.

공개 예시의 기한 차이는 합성 사례다. 이 시험으로 실제 조직의 시간 절감이나 모델 간 성능 순위를 계산하지 않았다.
