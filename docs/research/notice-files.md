# 별도 FAQ에서 찾은 사무용 가구 제한

2026년 예비창업패키지 모집공고에는 기계·설비·비품 구매비를 설명하는 행이 있다. 같은 게시물에 올라온 별첨 4 FAQ의 15쪽 4번 문답은 서랍이나 책상을 살 수 있는지 묻는다. 답변은 사무용 집기와 가구의 사업비 집행을 제한하고, 시제품 제작에 드는 재료와 외주 비용은 집행할 수 있다고 설명한다. 본문에서 채택한 구매 기준에 FAQ를 연결하면, 담당자는 두 문장을 함께 보고 지출 판단을 다시 할 수 있다. ## 국내 원문 시험

공고의 PDF 2쪽에서 기계장치 행을 채택했다. 같은 회차 FAQ, 전년도 FAQ, 같은 해의 사내벤처 FAQ를 각각 별도 파일로 가져왔다. 세 파일에는 같은 사무용 가구 제한 문장이 있다. 각 시험은 공고 본문만 먼저 읽은 상태에서 시작했고 본문 해시는 바뀌지 않았다. 실제 규정 개정일이나 FAQ 공개 순서를 재현한 실험은 아니다.

| 나중에 읽은 파일 | 재검토 | 확인된 근거 |
|---|---|---|
| 2026년 해당 공고의 별첨 4 FAQ | 열림 | 15쪽 4번의 사무용 집기 제한 |
| 2025년 같은 사업의 FAQ | 유지 | 연도 및 게시물이 다름 |
| 2026년 예비창업패키지 특화분야 사내벤처 FAQ | 유지 | 사업과 게시물이 다름 |
| 위 세 파일을 함께 추가 | 열림 | 해당 회차 FAQ 한 건만 표시 |
| 중소기업 정책자금 공고에 별도 참고자료 추가 | 열림 | 참고 14의 정책우선도 평가 면제 문장 |

사내벤처 FAQ는 중소벤처기업부 게시물의 별첨 4 HWPX다. 전년도 비교에는 가톨릭관동대학교 게시물의 2025년 별첨 4 PDF를 썼다. 정책자금 시험에서는 제2026-281호 본문의 평가 절차와 별도 참고자료의 AI 응용제품 신속 상용화 지원사업 선정기업 면제 문구를 연결했다. 이 면제는 본문에도 언급되며, 시험에서 새로 확인한 것은 첨부 원문과의 연결이다. ## 실제 폴더에서 사용하기

공식 게시물에서 본문과 별첨 목록을 확인한 뒤, UTF-8 Markdown으로 읽을 자료와 `folio-sources.json`을 한 폴더에 둔다. 아래는 구매 기준과 FAQ 하나를 등록하는 형식이다. 주소에는 확인한 자료의 HTTPS 주소를, 해시에는 해당 **Markdown 파일 바이트의 SHA-256**을 넣는다. 실험 스크립트는 공식 PDF·HWPX 원본의 SHA-256도 별도로 확인한다.

```json
{
  "version": 1,
  "sources": [
    {
      "path": "공고.md", "role": "notice", "year": 2026,
      "program": "예비창업패키지", "publication": "https://example.org/notices/207",
      "url": "https://example.org/files/notice.pdf", "sha256": "<공고 Markdown 해시>",
      "companions": ["https://example.org/files/faq.pdf"], "terms": ["기구"]
    },
    {
      "path": "별첨/FAQ.md", "role": "faq", "year": 2026,
      "program": "예비창업패키지", "publication": "https://example.org/notices/207",
      "url": "https://example.org/files/faq.pdf", "sha256": "<FAQ Markdown 해시>"
    }
  ]
}
```

일반 첨부는 역할을 `attachment`로 지정한다. `publication`, 연도, 사업명이 모두 일치하고 첨부 주소가 본문에 등록한 목록에 있어야 연결된다. 연결 가능 자료는 앱의 **원문 보관함**에서 확인할 수 있다. 파일을 다른 내용으로 교체했는데 등록 해시가 그대로이면 동기화 오류를 표시하고 마지막 정상 상태를 보관한다.

예외는 원 조항을 명시적으로 인용하거나, 등록한 기준어가 채택 문장 또는 제목과 첨부의 명시적 제한 문구에 함께 나올 때 검토한다. **첨부 근거 확인**을 누르면 결정 기록 전에도 매치된 문장과 행을 열 수 있다. 채택 당시 확인 가능한 첨부 근거는 결정 기록에 남는다. 사업 절을 지정한 결정에서는 첨부의 해당 절이나 첨부 등록 시 지정한 `scope`가 일치해야 한다. 대상명을 지정한 경우에는 예외에서 그 이름도 확인한다. 자료 등록과 변환은 담당자가 준비한다. 간접적인 예외나 서로 다른 표현으로 풀어 쓴 조항은 놓칠 수 있다.

결정을 다시 채택하면 당시 첨부 버전이 새 기준이 된다. 이후 파일이 빠지면 기존 문장을 보관함에서 계속 열 수 있고 화면은 그 근거를 현재 확인할 수 없다고 표시한다. 출처 목록이 없던 기존 결정은 채택 당시와 본문 파일 해시가 일치할 때에만 처음 연결한다.

## 다시 실행하기

Python과 `pdftotext`가 있는 환경에서 저장소 루트에서 실행한다. 스크립트는 공식 게시물의 첨부 링크와 원본 해시를 확인하며, 공고 행·FAQ 페이지·참고자료 문단을 Markdown으로 옮긴다. 각 시험의 입력 폴더에는 실제 경로와 해시가 채워진 출처 목록이 남는다.

```sh
python experiments/exceptions/notice_files.py --out notice-file-run
```
